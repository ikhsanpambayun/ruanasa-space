UI/UX SPECIFICATION DOCUMENT (UIUX-SPEC)

Ruanasa Space

Version: 1.5 (Updated)
Platform: Web-Based Responsive Application

User Interface Target:
- Participant: Mobile-first responsive web
- Admin: Desktop-first dashboard

------------------------------------------------------------------------

1. UI/UX OVERVIEW

UI/UX Ruanasa Space dirancang untuk memberikan pengalaman sederhana bagi participant dalam menemukan event, melakukan registrasi, pembayaran, hingga mengikuti aktivitas wellness.

Admin menggunakan dashboard desktop untuk mengelola seluruh operasional event secara efisien.

Semua peserta yang mendaftar event akan memiliki akun (termasuk melalui continue without login yang otomatis membuat akun), sehingga setiap peserta memiliki profil dan riwayat.

------------------------------------------------------------------------

2. DESIGN PRINCIPLE

Simple — Mengurangi kompleksitas proses registrasi. Participant dapat mendaftar event dalam hitungan menit dengan minimal input.

Trustworthy — Memberikan informasi jelas terkait event, harga, discount breakdown, pembayaran, dan status registrasi. Tidak ada biaya tersembunyi.

Operational Efficiency — Mempermudah admin mengelola event, peserta, pembayaran, dan feedback dalam satu dashboard tanpa berpindah platform.

Consistent — Menggunakan design tokens (warna, typography, spacing) yang konsisten di seluruh halaman untuk membangun familiarity.

Accessible — Touch-friendly untuk mobile, keyboard-navigable untuk desktop, readable font size, dan kontras warna yang memadai.

------------------------------------------------------------------------

3. DESIGN TOKENS

3.1 Color System

Primary: Brand color utama Ruanasa (digunakan pada CTA, active states, links).
Secondary: Warna pendukung (digunakan pada secondary buttons, accent elements).
Neutral: Skala abu-abu untuk text, border, background, divider.

Semantic Colors:
- Success (hijau): pembayaran berhasil, registrasi confirmed, present.
- Warning (kuning/amber): pending payment, pending registration, event almost full.
- Danger (merah): expired, failed, error states, delete action.
- Info (biru): informational badges, early bird, bundle discount.

3.2 Typography

Font Family: Sans-serif (contoh: Inter, Plus Jakarta Sans, atau sesuai brand guidelines).
Scale:
- Heading 1: 24px / bold — judul halaman.
- Heading 2: 20px / semibold — section title.
- Heading 3: 16px / semibold — sub-section, card title.
- Body: 14px / regular — paragraph text, form labels.
- Caption: 12px / regular — helper text, timestamps, secondary info.
- Overline: 11px / medium uppercase — badge text, status label.

3.3 Spacing

Menggunakan 4px base grid:
- 4px (xs), 8px (sm), 12px (md), 16px (lg), 24px (xl), 32px (2xl), 48px (3xl).
- Padding dalam card/container: 16px (mobile), 24px (desktop).
- Gap antar card/section: 16px (mobile), 24px (desktop).

3.4 Border Radius

- Small: 4px (input fields, badges).
- Medium: 8px (cards, buttons).
- Large: 12px (modal, bottom sheet).
- Full: 999px (avatar, circular badge).

5.3 Authentication Page

Trigger: Participant tap "Daftar Sekarang" dan belum login.

Layout: Single column, centered card.

Opsi yang ditampilkan:
- "Login with Google" (button dengan ikon Google)
- "Login with Email" (button)
- "Login with WhatsApp" (button)
- Divider: "atau"
- "Lanjutkan Tanpa Login" (text link atau secondary button)

5.3.1 Google Login Flow

Tap "Login with Google"
  → Redirect ke Google OAuth consent screen
  → Kembali ke app
  → Jika user baru: tampilkan form input Phone Number → Submit → Akun dibuat → Lanjut registrasi
  → Jika user existing: langsung lanjut registrasi

5.3.2 Email OTP Flow

Tap "Login with Email"
  → Form: input Email
  → Tap "Kirim OTP"
  → Form: input 6 digit OTP (auto-focus, auto-advance per digit)
  → Countdown timer "Kirim ulang OTP dalam 00:XX"
  → Jika valid & user baru: tampilkan form input Name dan Phone Number → Submit → Akun dibuat
  → Jika valid & user existing: langsung lanjut registrasi

Error States:
- OTP expired: "OTP sudah expired" + tombol "Kirim Ulang OTP"
- OTP salah: "Kode OTP salah, silakan coba lagi" (sisa percobaan ditampilkan)
- OTP salah 5x: "Terlalu banyak percobaan, silakan request OTP baru"
- Rate limit: "Terlalu banyak permintaan, silakan tunggu 15 menit"

5.3.3 WhatsApp OTP Flow

Sama dengan Email OTP, tapi input Phone Number di awal dan OTP dikirim via WhatsApp. Jika user baru, minta input Name dan Email setelah verifikasi.

5.3.4 Continue Without Login — Auto Account Creation Flow

Tap "Lanjutkan Tanpa Login"
  → Form:
    - Name (text input, wajib)
    - Phone Number (text input, wajib, placeholder: "08xxxxxxxxxx")
    - Email (text input, wajib)
  → Tap "Lanjutkan"
  → Loading state (spinner)
  → Sistem cek phone number:
    → DITEMUKAN:
      - Tampilkan inline alert (warning): "Nomor telepon ini sudah terdaftar."
      - Tampilkan sub-text: "Silakan login untuk melanjutkan."
      - Tampilkan tombol login options (Google, Email OTP, WhatsApp OTP)
      - Form tetap terlihat, tidak di-reset
    → TIDAK DITEMUKAN → sistem cek email:
      → DITEMUKAN:
        - Tampilkan inline alert (warning): "Email ini sudah terdaftar."
        - Tampilkan sub-text: "Silakan login untuk melanjutkan."
        - Tampilkan tombol login options
      → TIDAK DITEMUKAN:
        - Akun otomatis dibuat (auth_provider = auto_created)
        - Session aktif langsung diberikan
        - Redirect ke registration step berikutnya

5.4 Registration Flow (Multi-Step)

Layout: Single column dengan stepper/progress indicator di atas menunjukkan posisi saat ini.

Steps: Data Peserta → Jumlah & Nama → Add-on → Discount → Review

5.4.1 Step 1: Participant Data

Data auto-fill dari profil user (karena semua peserta punya akun):
- Name (text input, pre-filled, editable)
- Email (text input, pre-filled, editable)
- Phone Number (text input, pre-filled, editable)

Validation (inline, real-time):
- Email: format valid → jika tidak: "Format email tidak valid"
- Phone: format Indonesia (+62/08) → jika tidak: "Format nomor telepon tidak valid"

Duplicate check:
- Duplikasi dicek saat submit (Bayar Sekarang); jika ditolak (DUPLICATE_REGISTRATION), tampilkan "Anda sudah terdaftar pada event ini" (inline alert, danger)

Button: "Lanjutkan" (primary)

5.4.2 Step 2: Select Pax & Add Participant Names

Input: jumlah peserta (number stepper: - / + , minimum 1).
- Saat quantity berubah, sistem cek sisa slot:
  - Jika tidak cukup: "Slot tersisa hanya X, silakan kurangi jumlah peserta" (inline alert, warning)

Jika pax > 1:
- Tampilkan field nama per peserta tambahan (dynamic, muncul sesuai jumlah):
  - "Peserta 2" — Name (text input, wajib)
  - "Peserta 3" — Name (text input, wajib)
  - dst.
- Peserta 1 = buyer, sudah terisi dari step 1.

Jika pax = 1:
- Tidak ada field tambahan.

Bundle discount preview (jika berlaku):
- Tampilkan teks info: "Anda mendapatkan diskon 10% untuk 2 peserta!" (info color)

Button: "Lanjutkan" / "Kembali"

5.4.3 Step 3: Select Add-on

Jika event tidak memiliki add-on: skip step ini, langsung ke step 4.

Tampilkan daftar add-on yang Active dan available:
- Setiap add-on card menampilkan:
  - Add-on Name
  - Description (jika ada)
  - Price per unit
  - Quantity selector (- / +, min 0, max sesuai max_purchase_quantity)
  - Subtotal per add-on (price x quantity, update real-time)
- Jika available_quantity = 0: add-on tidak ditampilkan.

Running total di bawah: "Subtotal Add-on: Rp xxx"

Button: "Lanjutkan" / "Kembali"

5.4.4 Step 4: Apply Discount

Auto-applied discounts (read-only, informational):
- Early Bird: "Harga Early Bird diterapkan: Rp xxx/pax" (badge info)
- Bundle Discount: "Diskon 10% untuk 2 peserta diterapkan" (badge info)

Promo Code input:
- Text input: "Masukkan Kode Promo"
- Button: "Terapkan"
- Jika valid: tampilkan "Kode promo [CODE] berhasil diterapkan! Diskon: -Rp xxx" (success alert) + ikon X untuk hapus
- Jika invalid: tampilkan error message sesuai kasus:
  - "Kode promo tidak valid"
  - "Kode promo sudah expired"
  - "Kode promo sudah habis"
  - "Kode promo tidak aktif"

Button: "Lihat Ringkasan" / "Kembali"

5.4.5 Step 5: Order Review

Tampilkan ringkasan lengkap sebelum pembayaran:

Event Info:
- Event Name, Date, Time, Location (compact)

Participant List:
- Nama per peserta (numbered: 1. Sarah, 2. Budi, 3. Rina)

Price Breakdown:
- Harga per pax (normal/early bird): Rp xxx
- Jumlah pax: x orang
- Subtotal: Rp xxx
- Bundle Discount (jika berlaku): -Rp xxx (label: "Diskon 2 pax 10%")
- Add-on (per item):
  - [Nama Add-on] x [qty]: Rp xxx
- Subtotal Add-on: Rp xxx
- Promo Code (jika berlaku): -Rp xxx (label: "Promo [CODE]")
- Divider
- Total Payment: Rp xxx (heading, bold, prominent)

Button: "Bayar Sekarang" (primary, prominent) / "Kembali"

- Paid At (timestamp jika sudah Paid)

Actions:
- "Check Payment Status" button per row (trigger manual check ke payment gateway, hanya untuk status Pending)

Empty State: "Belum ada transaksi pembayaran untuk event ini."

6.9 Attendance Management

Diakses melalui: Event Detail → Tab "Attendance"

Layout: List atau table, optimized for quick check-in.

Search Bar: cari participant berdasarkan nama (real-time, prominent).

List item:
- Participant Name
- Attendance Status toggle (switch: Not Checked ↔ Present)
- Checked At timestamp (muncul setelah ditandai Present)

Filter: hanya menampilkan participant yang registration = Confirmed.

Summary di atas list:
- "Present: X / Y peserta (Z%)"

Empty State: "Belum ada peserta yang dikonfirmasi untuk event ini."

6.10 Discount Management (Promo Code)

Diakses melalui: Sidebar → "Promo Codes"

6.10.1 Promo Code List

Layout: Table.

Columns:
- Code
- Discount Type (Percentage / Fixed Amount)
- Discount Value
- Quota (used_count / quota, contoh: "12/50")
- Expiry Date
- Status (badge: Active / Inactive / Expired)

Filter: Status (All / Active / Inactive / Expired)

Actions per row: Edit, Toggle Status (Active/Inactive)

Tombol header: "+ Create Promo Code"

Note: Promo code yang sudah melewati expiry_date otomatis ditampilkan dengan badge "Expired" (read-only, tidak bisa diedit menjadi Active).

6.10.2 Create/Edit Promo Code Form

Fields:
- Code (text, wajib, alphanumeric, maks 20 karakter, auto-uppercase)
- Discount Type (dropdown: Percentage / Fixed Amount)
- Discount Value (number, wajib)
  - Jika Percentage: suffix "%", max 100
  - Jika Fixed Amount: prefix "Rp"
- Quota (number, wajib, min 1)
- Expiry Date (date picker, wajib, harus masa depan)
- Status (toggle: Active / Inactive)

Validation:
- Code sudah ada: "Kode promo ini sudah digunakan"

Actions: "Simpan" (primary) / "Batal"

7. SHARED UI COMPONENTS

7.1 Buttons

- Primary: brand color, digunakan untuk CTA utama (Daftar, Bayar, Publish, Simpan).
- Secondary: outline atau muted, digunakan untuk action sekunder (Kembali, Batal, Simpan Draft).
- Danger: merah, digunakan untuk destructive action (Hapus, Batalkan).

9. RESPONSIVE REQUIREMENT

9.1 Participant (Mobile-First)

- Minimum viewport: 360px.
- Single column layout.
- Sticky CTA bar di bottom (Daftar Sekarang, Bayar Sekarang).
- Touch-friendly: minimum tap target 44x44px.
- Swipeable cards (optional).
- Bottom sheet untuk pilihan dan filter.
- Font minimum: 14px body, 12px caption.
- Poster full-width, rasio 4:5.

9.2 Admin (Desktop-First)

- Minimum viewport: 1280px.
- Sidebar navigation (collapsible untuk tablet 768px+).
- Table layout untuk data lists.
- Dashboard menggunakan grid card layout.
- Modal untuk confirmations dan forms.
- Hover states pada interactive elements.
- Responsive breakpoints:
  - Desktop: ≥ 1280px (full sidebar + content)
  - Tablet: 768px - 1279px (collapsed sidebar, stacked cards)
  - Mobile: < 768px (hidden sidebar, hamburger menu, stacked layout)

10. UI STATE REQUIREMENT

10.1 Loading States

- Full page loading: centered spinner + "Memuat..." text.
- Skeleton loading: gray placeholder shapes (untuk card list, table rows, event detail).
- Inline loading: spinner kecil di dalam button saat processing (contoh: "Memproses..." saat submit).
- Lazy loading: poster images load saat masuk viewport.

10.2 Empty States

Setiap konteks memiliki empty state spesifik:
- Event Listing: "Belum ada event tersedia saat ini."
- Participant List: "Belum ada peserta terdaftar untuk event ini."
- Payment List: "Belum ada transaksi pembayaran untuk event ini."
- Attendance: "Belum ada peserta yang dikonfirmasi untuk event ini."
- Feedback: "Belum ada feedback untuk event ini."
- Event History (profile): "Anda belum mengikuti event apapun."
- Notification: "Tidak ada notifikasi baru."
- Template List: "Belum ada template. Buat template pertama Anda."
- Promo Code List: "Belum ada promo code."

10.3 Error States

- Form validation: inline error text di bawah field (danger color), field border berubah merah.
- API error: toast "Terjadi kesalahan, silakan coba lagi."
- Network error: toast "Koneksi internet terputus."
- Permission error: redirect ke halaman yang sesuai.

10.4 Success States

- Toast notification: "Event berhasil dipublikasikan", "Data tersimpan", "Pembayaran berhasil", dll.
- Inline success: checkmark icon + text (contoh: "Kode promo berhasil diterapkan!")
- Page-level success: Confirmation Page setelah pembayaran.
