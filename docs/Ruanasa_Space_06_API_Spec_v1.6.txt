API SPECIFICATION DOCUMENT (API-SPEC)

Ruanasa Space

Version: 1.6 (Updated)
Platform: Web-Based Responsive Application
Base URL: /api/v1

------------------------------------------------------------------------

1. API OVERVIEW

API Specification Document mendefinisikan kontrak komunikasi antara frontend application dengan backend system Ruanasa Space.

API mencakup:
- Authentication & Account
- User Profile
- Event Management (Public & Admin)
- Event Template (Admin)
- Instructor Management (Admin)
- Specialization Management (Admin)
- Registration & Pricing
- Add-on Management (Admin)
- Discount Code Management (Admin)
- Payment Processing
- Participant Management (Admin)
- Attendance Management (Admin)
- Feedback
- Notification (Admin)
- Analytics (Admin)
- Export (Admin)

------------------------------------------------------------------------

2. API STANDARD

2.1 HTTP Methods

- GET: retrieve data (idempotent)
- POST: create data atau trigger action
- PUT: full update
- PATCH: partial update
- DELETE: soft delete / remove

2.2 Response Format

Success:
{
  "success": true,
  "message": "Success message",
  "data": { ... }
}

Success with pagination:
{
  "success": true,
  "message": "Success",
  "data": [ ... ],
  "pagination": {
    "page": 1,
    "per_page": 20,
    "total_items": 85
  }
}

Error:
{
  "success": false,
  "message": "Human-readable error message",
  "error_code": "ERROR_CODE",
  "errors": {
    "field_name": ["Validation message"]
  }
}

2.3 Authentication Header

JWT token dikirim melalui dua mekanisme (backend harus support keduanya):
1. httpOnly cookie (primary — di-set oleh backend saat login response)
2. Authorization header: Bearer {jwt_token} (fallback — untuk API testing/mobile)

Prioritas: Cookie dicek terlebih dahulu, jika tidak ada maka cek Bearer header.

2.4 Content Type

Request: application/json (kecuali file upload: multipart/form-data)
Response: application/json

2.5 Pagination

Default: page=1, per_page=20
Query params: ?page=1&per_page=20

2.6 Date/Time Format

- Date: YYYY-MM-DD (contoh: 2027-03-15)
- Time: HH:mm (contoh: 08:00)
- Timestamp: ISO 8601 (contoh: 2027-03-15T08:00:00+07:00)

3. AUTHENTICATION API

------------------------------------------------------------------------

3.1 Google Login

POST /auth/google

Deskripsi: Login atau register menggunakan Google OAuth 2.0.

Request Body:
{
  "id_token": "string (Google ID token dari frontend)"
}

Response 200 (existing user):
{
  "success": true,
  "message": "Login berhasil",
  "data": {
    "token": "jwt_token",
    "user": {
      "id": "uuid",
      "name": "string",
      "email": "string",
      "phone_number": "string",
      "profile_picture": "string|null",
      "role": "participant",
      "auth_provider": "google"
    },
    "is_new_user": false
  }
}

Response 200 (new user — needs phone number):
{
  "success": true,
  "message": "Akun baru, lengkapi nomor telepon",
  "data": {
    "temp_token": "string",
    "name": "string (dari Google)",
    "email": "string (dari Google)",
    "is_new_user": true,
    "requires_phone": true
  }
}

Error 401:
{
  "success": false,
  "message": "Token Google tidak valid",
  "error_code": "INVALID_GOOGLE_TOKEN"
}

6.3 Create Event

POST /admin/events

Auth: Required (admin)

Request Body:
{
  "event_name": "string (max 150)",
  "activity_type": "string",
  "description": "string (max 5000)",
  "poster_url": "string",
  "date": "YYYY-MM-DD",
  "start_time": "HH:mm",
  "end_time": "HH:mm",
  "location": "string (max 500)",
  "instructor_id": "uuid",
  "capacity": 30,
  "template_id": "uuid|null"
}

Response 201:
{
  "success": true,
  "message": "Event berhasil dibuat",
  "data": { ... event object, status: "draft" }
}

Validation Errors 422:
- "Event name wajib diisi"
- "Tanggal tidak boleh di masa lalu"
- "End time harus setelah start time"
- "Instructor tidak ditemukan atau tidak aktif"
- "Kapasitas minimal 1"

------------------------------------------------------------------------

6.4 Update Event

PUT /admin/events/{id}

Auth: Required (admin)

Request Body: same as create (partial fields allowed).

Rules:
- Draft: semua field bisa diubah.
- Published: semua field kecuali activity_type bisa diubah.
- Completed: tidak bisa diubah.

Error 403:
- "Event yang sudah selesai tidak dapat diubah" / error_code: "EVENT_COMPLETED"

------------------------------------------------------------------------

6.5 Delete Event

DELETE /admin/events/{id}

Auth: Required (admin)

Rules: Hanya event berstatus draft yang bisa dihapus (soft delete).

Response 200:
{
  "success": true,
  "message": "Event berhasil dihapus"
}

Error 403:
- "Hanya event berstatus draft yang bisa dihapus" / error_code: "EVENT_DELETE_NOT_ALLOWED"

------------------------------------------------------------------------

6.6 Publish Event

POST /admin/events/{id}/publish

Auth: Required (admin)

Rules: Hanya draft yang bisa dipublish. Event harus memiliki minimal 1 normal price yang active, serta date, start_time, dan end_time yang sudah terisi (event hasil duplicate harus dilengkapi dulu).

Response 200:
{
  "success": true,
  "message": "Event berhasil dipublikasikan",
  "data": {
    "public_url": "string",
    "qr_code_url": "string"
  }
}

Error 400:
- "Event harus memiliki minimal satu harga normal" / error_code: "MISSING_PRICE"
- "Tanggal dan waktu event wajib diisi sebelum dipublikasikan" / error_code: "VALIDATION_ERROR"

Error 403:
- "Hanya event draft yang bisa dipublikasikan" / error_code: "INVALID_STATUS_TRANSITION"

------------------------------------------------------------------------

POST /admin/events/{id}/complete

Auth: Required (admin)

Rules: Hanya published yang bisa dicomplete. Triggers: kirim post-event notification (asinkron) ke buyer, berisi link feedback per participant yang present. Feedback token sudah dibuat saat payment confirmed.

Error 403:
- "Hanya event published yang bisa ditandai selesai" / error_code: "INVALID_STATUS_TRANSITION"

14.3 Payment Webhook (Payment Gateway Callback)

POST /payments/webhook

Auth: Signature validation (bukan JWT — sesuai format payment gateway provider)

Deskripsi: Endpoint yang dipanggil oleh payment gateway saat pembayaran berhasil.

Server-side actions (dalam satu database transaction):
1. Validasi callback signature.
2. Cari payment via payments.transaction_id (= order_id) dan verifikasi amount. Jika order_id tidak ditemukan (mis. transaksi lama yang sudah diganti metode) → catat log warning, balas 200, skip processing.
3. Idempotency check: jika payment sudah paid → return 200 OK, skip processing.
4. Jika registrasi sudah expired → jangan proses, catat log critical, balas 200.
5. Update payments.status -> paid, payments.paid_at -> now.
6. Update registrations.payment_status -> paid dan registrations.registration_status -> confirmed.
7. Buat attendance records (not_checked) untuk setiap participant.
8. Buat baris feedback (token unik) untuk setiap participant.
9. Kirim WhatsApp notification (registration confirmation) ke buyer.
10. Kirim admin notification (admin_payment_success).
11. Cek kapasitas event, kirim admin notification (admin_event_almost_full) jika sisa <= 10%.

Response 200: { "status": "ok" }

21. SECURITY REQUIREMENT

21.1 Authentication & Authorization

- JWT token: HS256, expiration 7 hari (sliding), delivered via httpOnly cookie + Bearer header support.
- Admin: email + password (bcrypt 12 rounds).
- Participant: passwordless (Google OAuth, OTP, auto-create).
- Role-based access: admin endpoints (/admin/*) hanya bisa diakses role = admin.
- Resource ownership: participant hanya bisa GET registrasi miliknya sendiri.
- Feedback token: unique per participant per event, token di-generate saat payment confirmed, akses tanpa login.

21.2 OTP Security

- 6 digit, hashed sebelum disimpan.
- Expired: 5 menit.
- Max attempts: 5 per session.
- Rate limit: 3 request per 15 menit per phone/email.

21.3 API Security

- HTTPS (SSL/TLS) wajib.
- Input validation & sanitization semua endpoint.
- Parameterized queries (prevent SQL injection).
- XSS protection.
- CORS: hanya domain frontend yang diizinkan.
- Rate limiting:
  - Auth endpoints: 10 req/menit per IP.
  - Public event list: 60 req/menit per IP.
  - Registration: 5 req/menit per user.
  - Auto-create account: 5 req/menit per IP.

21.4 Payment Security

- Webhook signature validation.
- Idempotency (mencegah double processing callback).
- Transaction ID disimpan sebagai referensi.

23. WEBHOOK & SCHEDULED JOB REFERENCE

23.1 Payment Webhook

Endpoint: POST /payments/webhook
Trigger: Payment gateway callback saat pembayaran berhasil.
Actions: update payment + registration status, create attendance records, send WhatsApp + admin notifications, check event capacity.

23.2 Payment Expiration Job

Schedule: */5 * * * * (setiap 5 menit)
Logic: SELECT registrations WHERE registration_status = 'pending' AND payment_deadline < NOW().
Actions:
1. Set registration_status → 'expired', payment_status → 'expired'. Registrasi TIDAK di-soft-delete (deleted_at tetap NULL).
2. Return event slots (recalculate capacity).
3. Return add-on available_quantity.
4. Return discount code used_count (jika discount_code_id not null).

23.3 Event Reminder Job

Schedule: 0 1 * * * (setiap hari pukul 08:00 WIB = 01:00 UTC)
Logic: SELECT events WHERE status = 'published' AND date = CURRENT_DATE + 1.
Actions: Send WhatsApp reminder ke semua buyer dengan registration_status = confirmed. Phone number diambil dari users.phone_number via JOIN registrations.buyer_user_id.

23.4 Post Event Notification

Trigger: Otomatis saat event di-complete (asinkron); job harian hanya catch-up untuk event completed dengan post_event_sent = false; admin bisa trigger manual via POST /admin/events/{id}/send-post-event.
Actions:
1. Feedback tokens sudah di-generate saat payment confirmed. Post-event hanya mengirim link feedback.
2. Satu pesan WA ke setiap buyer confirmed, berisi link feedback untuk setiap participant miliknya yang attendance = present. Phone number diambil dari users.phone_number via JOIN registrations.buyer_user_id.
3. Set events.post_event_sent = true setelah selesai.
